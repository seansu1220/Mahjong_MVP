# 本專案採用的麻將規則

> 台灣 16 張，取各地最普遍的算法。
> **這份文件就是規格書**——程式裡的判定完全依照本表，本表沒列的一律不實作。
> 客戶若採不同算法，修改 `FanTable` 的設定即可，不需改動 `ScoreCalculator`。

## 一、基本設定

| 項目 | 本專案採用 | 程式位置 |
|---|---|---|
| 底 | 100 點 | `FanTable.BaseDi` |
| 每台 | 100 點 | `FanTable.PerTai` |
| 總牌數 | 144 張（數牌字牌各 4 張、花牌 8 張各 1 張） | `Wall` |
| 發牌 | 莊家 17 張、閒家 16 張 | `GameState.CreateNewHand` |
| 胡牌型 | 5 組面子 + 1 對將 | `WinChecker.CanWin` |
| 七對子 | **不成立** | 同上 |
| 補花 | 摸到花自動從**牌山尾端**補，補到不是花為止 | `GameState.DrawReplacementTile` |
| 吃 | 只能吃**下家**打出的牌 | `GameState.IsNextSeatOf` |
| 動作優先權 | 胡 > 碰/槓 > 吃 | `TurnEngine`（實作中） |
| 多家可胡 | 逆時針方向離打牌者近者優先 | `GameState.SeatDistance` |
| 流局 | 牌山抽乾 | `GameState.IsWallExhausted` |

計分公式：**應收點數 = 底 + 台數 × 每台**

## 三、四個有爭議的判定，我們選了什麼

以下四項各地差異最大，這裡列出**我們的選擇**與**另一種常見算法**。
客戶若要改，改的是設定不是程式。

### 1. 正花不另外加台

- **我們採用**：所有花牌一律每張 1 台，正花不再多加。
- 另一種算法：正花額外再加 1 台（一張正花共 2 台）。
- 設定：`FanTable.ZhengHuaStacksWithFlower = false`

> 說明：花牌有 8 張，每個座位對應其中 2 張叫「正花」。
> 採每張 1 台最單純，也最好向玩家解釋。

### 2. 大牌不重複計小牌

- **我們採用**：大三元／小三元成立時不再另計三元牌；大四喜／小四喜成立時不再另計門風、圈風。
- 另一種算法：大牌之外，裡面的每組字牌刻子仍各自計台。
- 設定：`FanTable.DragonTilesCountWithBigDragons = false`、`FanTable.WindTilesCountWithBigWinds = false`

> 說明：大三元 8 台本身就是「湊齊中發白三組刻子」的獎勵，
> 再把三組三元牌各 1 台加上去等於同一件事算兩次。

### 3. 平胡必須兩面聽

- **我們採用**：平胡要求全順子、將是數牌、非自摸，**且必須兩面聽**。
  邊張（89 聽 7）、嵌張（13 聽 2）、單吊、對倒都不算平胡。
- 另一種算法：不要求兩面聽，只要全順子即可。
- 設定：`FanTable.PinghuRequiresTwoSidedWait = true`

### 4. 平胡不要求無花

- **我們採用**：有花牌仍可算平胡。
- 另一種算法：手上有花就不算平胡。
- 說明：「無花才算平胡」屬少數規則，本專案不採用，故未實作。

## 四、明刻與暗刻的認定

這一條會直接影響五暗刻等台數，特別說明：

- **自摸**完成的刻子 → 暗刻
- **放槍**（別人打出的牌）完成的刻子 → **明刻**
- **暗槓** → 暗刻，且不破門清
- **明槓／碰** → 明刻

當一副牌有多種拆解方式時，程式取**台數最高**的那一種。
放槍時若胡牌張同時可解釋成順子或刻子，優先解釋為順子，
讓刻子保有暗刻身分——這與「取最高台」的慣例一致。

## 五、聽牌宣告（畫面功能，不計台）

畫面上提供一個「聽」按鈕：當你打掉剛摸的那張之後仍然聽牌時才會出現。
按下去之後牌型就固定，之後每一輪自動打掉摸進來的牌，只有能胡才會停下來，
也不再吃碰槓。

這純粹是**操作上的便利**，方便展示時快速把一局打完，
**沒有任何台數效果**——台灣 16 張沒有日本麻將的立直，本專案也不實作。
台數表裡沒有這一項。
